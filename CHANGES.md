# inlet spec: changes

## Changes, by weight

- **Cells.** Every worker runs in a cell: user and mount namespaces plus `pivot_root`, and/or Landlock, built in Rust, with a dedicated uid when root. That holds under every isolator. No cell means the gate denies. The bwrap row is gone. Why: cgroup, rlimit, and slurm hide nothing from a worker with the same uid, so "every isolator" never hid the ledger, keys, or operator socket.
- **Purse is admits and exits.** The child-slice rule stays. The debit is the admit record and the refund is the exit. A task with no exit at restart is charged its whole token slice. Memory and pids return when the process is gone, so a requeue can be placed. `cost` is telemetry. The proxy clamps max output tokens to the remainder. Why: costs flushed every 50ms let a restart double-spend, against step 11.
- **Admit durable before exec.** The fsync list is now admit with its debit, accepted `add` batches, `bind`, `clear`, promote, sign, and purse `reset`. One log file, so a refund is always on disk before an admit that spends it. Why: "fsync before a spawn" never said the debit was durable, and a lost constraint would loosen admission.
- **Signing needs a passphrase.** `inlet init` makes a passphrase-wrapped ed25519 key and pins the public half. `sign` reads the passphrase from `/dev/tty`. The skill now says edit `policy.draft.lua`, show `inlet diff`, stop. Why: Pi and Wizard share the operator socket, so "human-signed" was honor system.
- **Gate in tokens.** `value` is tokens, default `value = 400000` against `default_budget.tokens = 200000`. With your off rule (p = 1 verified, 0.5 not) and a cold cost equal to the budget, a verified task passes when budget ≤ value, an unverified one when budget ≤ value/2. Why: value 1 against a token cost denied everything at `min_ev = 0`. A fixed default keeps your bias toward denying fat requests.
- **Never fail open, including the gate purse.** The gate purse is `decision.purse_tokens` and belongs to the supervisor. Empty counts as a down endpoint, so spawns deny. A full `live` keeps a task queued. Other failed checks deny. Why: the purse had no key or owner, and "allow only if live < max_live" read as a deny for 10k queued tasks.
- **Constraints judgeable with the endpoint off.** `#tags` in `/bind` text scope a constraint. With the endpoint off it blocks those tags, and an untagged one is refused. With it on, the endpoint judges conflict. Clearing needs the passphrase. Why: nothing could decide whether free text "conflicts" with the endpoint off, and an agent could clear your constraint from the CLI.
- **Human weight scoped.** TUI text posts as `you` at `human_weight`. `inlet post` posts as `operator` at weight 1. The spec now lists what the endpoint receives and says weight is inert with it off. Why: operator agents on the CLI would otherwise post with human weight.
- **No-verifier tasks.** Operator agents may `inlet add --no-verify` without the passphrase. It goes through the gate at p = 0.5 and never promotes. Workers can't request unverified children. Why: "a human constraint admitted it" was impossible, since constraints only block.
- **Root purse defined.** `max_tokens`, `max_memory_mb`, and `max_pids` are supervisor-wide totals, and root tasks slice from them. `max_tokens` is the signed cap on the status line. It resets on `caps.token_period` (default `1d`). The reset is a ledger record and does not refund a live slice twice. Why: per-task or global was ambiguous, and a purse that never resets is not how a factory is budgeted.
- **Promotion can't be passed with `true`.** Before a second-run pass counts, the verifier runs against a stub `run` that exits 0. Passing the stub means the recipe can only be pinned. Why: the author writes `meta.json`'s verifier.
- **`unattended` made explicit.** With `false`, a second-run pass marks the recipe ready for `/pin`. With `true`, it promotes. Why: the text implied this but never said what attended mode does with a pass.
- **Policy drafts are operator-only.** `policy.draft.lua` sits outside every cell. Worker drafts are recipe drafts. The preamble is part of the signed snapshot. Why: "an agent can write a draft" sat next to "workers cannot change policy".
- **Intake and CLI parity.** Added `inlet add` (flags, or `-f tasks.jsonl` under one fsync), `default_budget`, `/add`, `inlet init`, `inlet clear`, and `inlet shell`, plus a `task` record. `bind` and `clear` became record kinds. `inlet` means `inlet attach`. `/follow` maps to `watch --worker`, `/quit` to Ctrl-C. Why: nothing could enqueue a task, and `/clear`, `inlet shell`, and constraints had no CLI or record.
- **Ledger framing.** Records are `len | crc32 | json`. A bad final record is truncated. A bad record followed by good ones stops the daemon. The snap index carries a log offset so restart replays only the tail. Why: a length alone can't tell a torn tail from garbage.
- **`kind` dropped from the task.** Worker tags merge into task tags. `ctx.tags` is a set, so the example reads `ctx.tags.math`. The cost median is keyed by worker and tag set. Why: `ctx.tag` didn't exist, and kind repeated the worker's tags.
- **Network stated.** Per-worker `net`. Code workers default to `host`: no keys, but a worker can still send its workdir out. Math workers (tagged `math`, not `code`) default to `none`, where the unix-socket proxy keeps working. Explicit `net` wins. Why: without a network namespace, the cell doesn't stop exfiltration, and code workers still need registries.
- **Crash policy stated.** `on_crash` is per worker. Math defaults to requeue as a new admission. Code stays failed. The crashed token slice stays spent. Why: sweeps want another try; a long-lived code task should not respawn itself.
- **`blocked` defined.** It means admitted and alive, waiting on an ask or a child. `failed` carries a reason.
- **Debug vs transcripts.** Your levels 0–4 stay. Levels 0 and 1 are ledger records and always kept. Levels 2–4 are socket-only. Transcripts are worker stdio in `runs/<id>.log`, capped at 16MB. Why: "dropped at ingest" and "transcripts on disk" read as a contradiction.
- **Config precedence.** The preset fills what the file leaves out, and explicit keys win. Why: `setup = "box"` next to an explicit `caps` table was ambiguous.
- **Replication wording.** "Conflicts on the log are impossible" became "an admit with a losing fence is rejected".
- **Lua sandbox tightened.** `package` is also not loaded, `load` is text-only, and an instruction budget makes an overrun a deny. Why: `require` and bytecode are escape hatches, and a looping `admit` would stall the gate.
- **Bounds.** The 5ms admission budget leaves out the fsync, and concurrent admits share one. Workers get `PDEATHSIG`. Why: a laptop fsync can take more than 5ms on its own, and orphans could outlive a crashed daemon.
- **Token efficiency.** Preamble, gate payload, and proxy are on a diet. The proxy forwards once, patches only the output cap, and does not retry. Why: the model path is the bill.
- **Prose and markdown.** tinygrad aside cut. Rust 1.95, `/sys/fs/cgroup`, and bwrap moved to Environment. The tree, registry, slash list, and Lua indentation are restored. The isolator and debug tables are real tables, and task fields are a table. The isolation fence is called a "cell" so it doesn't clash with the lease `fence`.

## Settled

- Code workers default to `net = "host"`. Math workers default to `net = "none"`.
- `max_tokens` resets on a configurable period, daily by default. The reset is a ledger record and never refunds a live slice twice.
- Operator agents may enqueue `--no-verify` without the passphrase. Gate at p = 0.5, never promote.
- Optimize the model path: preamble, gate payload, proxy overhead, no re-sent context.
- Crashed math-style tasks requeue as a new admission. Long-lived code tasks stay failed. `on_crash` is the per-worker setting.

## Owner decisions

- Two first-class doors. The group chat is humans and agents together: humans are role `human`, `@all` and `@<id>` address a post, channels by tag come as the room scales, and a bridge (Telegram first) is just another operator-socket client posting with the human tag and the human weight. The operator agent is Pi or Wizard with the skill. The human talks to that agent; it runs the CLI. inlet may run in a container. The mounted operator socket is the hole.
- The group chat is also how agents talk to each other and vote. Workers post to channels, read the channels that match their tags, `@mention` each other, and cast votes on board questions (which approach, whether a recipe is worth pinning, whether a worker is spam). This replaces the preamble line "do not message a sibling": there is no private sibling channel. Talk goes through the board.
- Consensus moderates the board only. A vote can mute, demote, move a worker out of a channel, flag them for the operator, or recommend a pin. Votes are weighted ledger records. Humans weigh most, because the workers are an interested party. Votes never admit, change caps, change budgets, or kill. Those stay with the gate and the operator. This revises "agent voting is not a gate": voting is real, and it is not a gate.
- Posts store `role`, `channel`, and `mentions` from the first TUI step, so channels and votes do not migrate the log. Routing, tallies, and bridges are later build steps. Steps 1–4 do not grow a second chat system.
